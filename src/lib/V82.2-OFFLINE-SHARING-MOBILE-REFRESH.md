# v82.2 — Offline Sharing, Silent Refresh & Mobile Navigation

## User-visible behavior

- Closed Trips never appear on the signed-in Offline screen or the standalone offline fallback. Older closed packs are removed from device storage the next time they are read.
- Offline Quick Expense now includes **Everyone**, **Only me**, and individual traveler checkboxes. Everyone remains the default. All Trip members can view the synced expense, while the equal cost split is assigned only to the selected travelers.
- Reconnection still syncs queued changes automatically to their original Trip. A successful sync now triggers immediate background data refresh for the live Home wallet and Settlement workspace; no route loading screen or full-page refresh is used.
- Mobile navigation is rendered directly under `document.body` and explicitly fixed to the visual viewport on phone widths. This prevents a long Settlement page or an ancestor layout context from positioning the bar inside page content.

## Closed-Trip defense layers

1. The Offline page supplies only open Trips.
2. `/api/offline-pack` refuses closed Trips and excludes them from all-Trip warmup.
3. Local pack reads and writes filter and purge closed packs, including the selected legacy mirror.
4. `public/offline.html` performs the same filter before rendering.

Pending offline mutations are not silently deleted. If a Trip closes after an expense was queued, the existing v82 permanent-failure handling keeps that mutation reviewable instead of retrying forever.
